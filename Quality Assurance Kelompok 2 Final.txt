Pengantar Dokumen
Dokumen Quality Assurance (QA) ini disusun secara khusus untuk memandu proses
pengujian aplikasi Si-Abas Islamiyah. Mengingat aplikasi ini mengusung model Guru-Centric
di mana guru menjadi satu-satunya operator presensi, pengujian akan sangat menitikberatkan
pada kemudahan penggunaan antarmuka, kecepatan pemrosesan biometrik, dan keandalan
sistem dalam memvalidasi lokasi. Dokumen ini memastikan bahwa seluruh spesifikasi yang
tertuang dalam Software Requirements Specification (SRS) dapat diimplementasikan dengan
baik tanpa kendala teknis di lapangan.

1. Test Plan (Rencana Pengujian)
1.1 Tujuan Pengujian
Tujuan utama dari pengujian ini adalah untuk memvalidasi bahwa aplikasi SiAbas siap dioperasikan dalam lingkungan sekolah dasar yang dinamis. Secara spesifik,
pengujian ini bertujuan untuk:
a.

Memastikan aplikasi mampu mempercepat proses absensi kelas hingga selesai di
bawah 3 menit untuk total 30 siswa, sehingga tidak memotong waktu efektif
kegiatan belajar mengajar.

b.

Menguji keandalan algoritma face recognition dan liveness detection guna
mencegah manipulasi presensi menggunakan foto atau topeng.

c.

Memverifikasi bahwa sistem geofencing bekerja akurat untuk mengunci akses
aplikasi jika perangkat guru berada di luar radius 100 meter dari koordinat sekolah.

1.2 Ruang Lingkup (Scope)
Pengujian pada fase ini difokuskan pada aplikasi mobile di sisi Klien (Guru).
Lingkup pengujian mencakup:
a.

Modul Autentikasi: Proses login dan perlindungan sesi pengguna.

b.

Modul Validasi Lokasi (GPS): Kinerja sensor geofencing secara real-time.

c.

Modul Pemindaian Biometrik: Kecepatan, akurasi pemindaian wajah, serta
penanganan saat verifikasi gagal (input manual).

d.

Modul Transmisi Data: Sinkronisasi laporan harian ke server dan trigger
pengiriman notifikasi otomatis melalui WhatsApp Gateway.

1.3 Lingkungan Pengujian (Test Environment)
Untuk mendapatkan hasil yang paling mendekati skenario penggunaan nyata,
pengujian harus dilakukan dengan parameter lingkungan berikut:
a.

Perangkat Keras: Smartphone dengan kamera beresolusi minimal 5MP dan modul
GPS yang berfungsi baik.

b.

Sistem Operasi: Diuji pada dua ekosistem, yaitu minimal Android 9.0 dan iOS 14.0.

c.

Koneksi Jaringan: Pengujian dilakukan pada kondisi jaringan stabil minimal 3
Mbps, serta diuji pula saat koneksi terputus total untuk memvalidasi fitur offline
mode.

d.

Kondisi Fisik Ruangan: Pencahayaan kelas disimulasikan pada kondisi standar
(sekitar 300 lux) untuk mengukur False Acceptance Rate.

4. Bug Report (Pelaporan Cacat Sistem)
Berikut adalah daftar Bug Report dari hasil temuan pengujian:

Bug ID          : BUG-001 (Dari TC-06)
Judul Bug       : Data Presensi Tidak Tersimpan Lokal Saat Mode Luring (Offline)
Dilaporkan Oleh : Tester
Tanggal Temuan  : -
Environment     : Android/iOS
Langkah Mereproduksi:
1. Matikan paket data / Wi-Fi perangkat.
2. Lakukan presensi penuh satu kelas.
3. Nyalakan internet kembali, lalu selesaikan sesi.
Expected Result : Data tertahan di penyimpanan lokal dengan aman (Buffer) dan terkirim otomatis saat internet pulih.
Actual Result   : Sistem gagal menyimpan presensi lokal, data presensi yang dilakukan saat offline hilang saat koneksi kembali.
Severity        : Critical
Lampiran        : -

Bug ID          : BUG-002 (Dari TC-03)
Judul Bug       : Response Time Pemindaian Biometrik Kurang Cepat
Dilaporkan Oleh : Tester
Tanggal Temuan  : -
Environment     : Android/iOS
Langkah Mereproduksi:
1. Buka kelas dan arahkan kamera ke wajah siswa.
2. Lakukan proses scanning.
Expected Result : Sistem mencocokkan wajah dan merespons dalam waktu kurang dari 2 detik per siswa.
Actual Result   : Proses pencocokan wajah terkadang membutuhkan waktu lebih dari 2 detik.
Severity        : Medium
Lampiran        : -
